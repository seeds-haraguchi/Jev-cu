# カレンダー移動デモ（実行前の案）

目的：実際の画面から Jev がコントロールを選び、Computer Use が実行し、Codex が結果を読み取って検証する流れを示します。表示と閲覧する日付だけを変更し、予定は作成・変更しません。

先にユーザーへ、月表示 → 次の月 → 今日に戻る → 週表示、という順序を説明します。終了時は今週の表示にします。ユーザーが元の表示への復帰を求めた場合は、復帰を別の段階として扱います。

## 段階と検証

| 段階 | Jev の目標 | 成功の証拠 |
| --- | --- | --- |
| 月表示 | Switch Calendar to Month view. | month-button が選択されている |
| 次の月 | Navigate to the calendar month immediately after the observed starting month. | 段階の開始時点から目標年月を計算し、タイトルと一致する |
| 今日 | Return to today in Calendar. | 現在の年月が一致し、アクティブまたは選択された日付がローカルの今日である。Today ボタンの存在だけでは不十分 |
| 週表示 | Switch Calendar to Week view. | week-button が選択され、表示範囲に今日が含まれる |

実行前に再観測して実際のラベルと状態の形式を確認し、ローカルの日付から目標を計算します。過去の月、AX インデックス、例示の日付をハードコードしません。AX から日付状態を確実に読めない場合は、Codex が画面を確認してその旨を記録し、スクリーンショットを Jev に送信しません。

実際に実行する段階を 1 つ先にプレビューします。各段階は最大 2～3 ステップまで試し、完了してから次へ進みます。ダイアログが出た、ユーザーが画面を変更した、期待した変化を観測できない場合は、その段階を一時停止して再判断します。

## 記録

各段階の目標、実際の前後状態に必要な要約、軌跡パス、Jev の呼び出し数、実操作数、合計時間、検証結果、引き継ぎ理由を保存します。関係のない予定本文は保存しません。

これは操作経路のデモであり、他の方法より費用や速度が優れている証拠にはなりません。比較実験では同じ開始状態と成功判定を使い、失敗と引き継ぎも集計します。
